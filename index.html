第一期核心修正案例

问题根源：原版 Motrix 以 actuator_ctrl_limits（物理限位）作为动作空间边界，配合 action_scale=0.05。后续调参时将 action_scale 改为 0.25，但未同步修改动作空间边界。

实际影响：calf 关节动作空间异常（范围全为负值），与归一化动作空间语义不等价。

修正方案：

python
# 修正前：以物理限位作为边界
gym.spaces.Box(actuator_ctrl_limits[0], actuator_ctrl_limits[1], ...)

# 修正后：固定归一化范围
gym.spaces.Box(-np.ones(n), np.ones(n), ...)
常见问题

问题解答

训练营高频问题与踩坑总结，帮助你快速定位并解决训练中的典型问题

Q
训练时奖励不收敛，应该从哪些方面排查？

排查顺序：

  1. 检查物理层：机器人是否一开始就抖动、穿模或爆炸？先确认模型和仿真参数正确。
  2. 检查奖励函数：奖励方向是否与目标一致？信号密度是否足够？是否存在奖励漏洞？
  3. 检查观测空间：是否包含决策所需的全部关键信息？是否做了合理的归一化/编码？
  4. 检查动作空间：边界定义是否合理？与 action_scale 是否对齐？
  5. 检查终止条件：是否过严导致 episode 过早结束，样本不足？
  6. 检查算法参数：学习率、PPO clip 范围、批次大小等是否与环境复杂度匹配。
Q
动作空间边界应该如何设置？物理限位还是固定归一化？

推荐做法：使用固定归一化范围 [-1, 1]

原版 Motrix 以 actuator_ctrl_limits（物理限位）作为动作空间边界，配合 action_scale=0.05。若后续调参时只改 action_scale 而不同步修改边界，会导致动作空间语义不一致（如 calf 关节范围全为负值）。

修正方案：将动作空间边界改为固定的 [-1, 1]，使其与归一化动作空间完全对齐。这样无论 action_scale 如何调整，边界语义始终等价。

Q
如何快速读懂一个 MotrixLab Demo？

四步分析法：

  1. 任务了解：这个机器人要做什么？目标状态是什么？
  2. 要素分解：列出观测、动作、奖励、终止四个核心要素。
  3. 配置追踪：找到 EnvCfg，看参数如何定义仿真步长、 episode 长度、初始状态等。
  4. 深入代码：看 Reward 的 compute 方法，看 Env 的 step 和 reset 逻辑，确认动作如何映射到关节。
Q
训练环境创建失败，通常是什么原因？

常见原因：

  • 模型文件路径错误：EnvCfg 中 model_file 指向的 XML/URDF 不存在或路径错误。
  • 注册名不匹配：命令行中的环境名与 @envcfg("name") 或 @registry 中的注册名不一致。
  • 依赖缺失：Motrix 物理引擎或其他依赖未正确安装。
  • 配置冲突：EnvCfg 和 RLCfg 的字段类型或默认值冲突导致实例化失败。
Q
为什么要在训练前先看训练过程中的行为视频？

奖励曲线（reward curve）只能告诉你"数值在上升"，但无法告诉你"机器人在做什么"。行为视频是诊断训练质量的关键手段：

  • 是否出现"作弊"行为（利用奖励漏洞）？
  • 是否因为关节抖动或物理不稳定导致训练失败？
  • 目标动作是否被执行，还是机器人只在做原地踏步？
  • 终止条件是否被正确触发？

建议：每训练一段时间就用 play.py 或 view.py 查看一次行为，至少每周看一次。
